# 3x-ui 3.8.5 — управление VK/Телемостом, patch 2

Отдельная сборка панели с разделом **«Туннели»**. Подключение существующих туннелей проверено на действующих серверах. Бинарник Xray в архив не входит и установщиком не меняется.

## Что есть

- установка одной пары VK и одной пары Телемост: клиент на текущей панели,
  сервер — на выбранной зарубежной ноде;
- подключение существующих служб без их переустановки;
- состояние обоих концов, проверка HTTPS через SOCKS и показ выходного IP;
- создание локального SOCKS outbound после успешной проверки;
- смена ссылки и перезапуск: у Телемоста меняются оба конца, у VK — только клиент;
- отдельный перезапуск обоих концов выбранного туннеля;
- проверки API-токенов, параметров, портов, контрольных сумм бинарников;
- резервная копия конфигурации перед сменой ссылки и откат при ошибке перезапуска.

Балансеры и правила маршрутизации не изменяются. Клиенты/UUID/подписки не
импортируются и не редактируются. Добавленный outbound затем выбирается в
обычном интерфейсе маршрутов/балансеров.

## Совместимость

Только **3x-ui 3.8.5**, Linux amd64, systemd ≥247, Python 3. Панели, устанавливающие
службы, должны работать от root. Нода должна быть доступна по HTTPS с API-токеном
области **admin**. Токены monitor/node-sync для этих операций не подходят.
Патч нужен на главной панели и на каждой управляемой ноде. Установка одного
бинарника только на главной панели не добавит API управления туннелями на зарубежной ноде.

Поддерживаются службы из подготовленных ранее архивов:

| Канал | Служба | Конфигурация |
|---|---|---|
| VK | `turnrelay-vk` | `/etc/turnrelay-vk/config.json` |
| Телемост | `olcrtc-telemost` | `/etc/olcrtc/telemost.yaml` (JSON-совместимый YAML) |

Произвольные YAML-конфиги и сторонние варианты service-unit в эту версию не входят.
Панель управляет только этими фиксированными службами, команды из браузера не исполняет.

## Установка панели на чистую VPS

Поддерживаются Ubuntu 24.04–26.x и Debian 12–13, amd64, systemd. На новой VPS выполни:

```bash
curl -fL https://github.com/danilov76/3x-ui/releases/download/tunnels-3.8.5-patch2/install-fork.sh -o install-fork.sh
sudo bash install-fork.sh --host YOUR_SERVER_IP
```

Вместо `YOUR_SERVER_IP` укажи публичный IP или домен VPS. Порт панели по умолчанию **2053**; другой можно задать через `--port 10575`.

Установщик ставит зависимости, загружает закреплённые по SHA256 архивы, берёт Xray и сопутствующие ресурсы из официальной 3.8.5, а панель и движки туннелей — из этого форка. Оригинальная панель не запускается. Создаёт SQLite, случайные логин/пароль, HTTPS-сертификат и службу `x-ui` с автозапуском. Проверяет сохранённые настройки и локальную доступность панели.

Адрес и данные входа сохраняются только на сервере в `/etc/x-ui/fork-install.txt` с доступом root. Прочитай этот файл в своём SSH-терминале; не публикуй его содержимое. Разреши входящий TCP 2053 (или выбранный порт) в firewall VPS и хостинга.

Первый сертификат самоподписанный, срок — год: браузер покажет предупреждение. Для подключения панели как ноды установи доверенный HTTPS-сертификат через настройки панели. Автоматического получения/продления сертификата этот установщик не делает.

Инбаунды, клиенты, звонки и пары туннелей автоматически не создаются. Установи форк на главном сервере и ноде, затем настрой ноду и раздел «Туннели». Telegram и двухфакторная авторизация настраиваются отдельно.

Повторный запуск при наличии панели или конфигурации отказывается продолжать. Если установка оборвалась после записи файлов, служба останавливается, файлы сохраняются для диагностики. Путь к закрытому логу выводится в терминале. Это не скрипт обновления: для существующей панели используй раздел ниже.

Проверены распаковка реальных архивов, создание новой SQLite-базы реальным бинарником, параметры панели и создание пользователя; тестами проверены отказ от перезаписи и небезопасных архивов. Полный запуск на чистой VPS с apt/systemd пока не проверен.

## Как обновить панель

Сначала проверь сборку на отдельной VPS или копии окружения. Плановый порядок
для рабочих машин: зарубежные ноды → главная панель. Перезапуск x-ui может кратко оборвать
VPN-соединения. Самостоятельное обновление панели из upstream затрёт патч.

Скачай комплект и проверь контрольную сумму:

```bash
curl -fLO https://github.com/danilov76/3x-ui/releases/download/tunnels-3.8.5-patch2/3x-ui-tunnels-linux-amd64.tar.gz
curl -fLO https://github.com/danilov76/3x-ui/releases/download/tunnels-3.8.5-patch2/3x-ui-tunnels-linux-amd64.tar.gz.sha256
sha256sum -c 3x-ui-tunnels-linux-amd64.tar.gz.sha256
tar -xzf 3x-ui-tunnels-linux-amd64.tar.gz
cd 3x-ui-tunnels-release-3.8.5
```

Проверь содержимое комплекта:

```bash
sha256sum -c SHA256SUMS
```

### SQLite (например, главная панель)

Подставь действующий порт и базовый путь панели:

```bash
sudo bash install-panel.sh --db sqlite \
  --health-url 'https://127.0.0.1:2053/YOUR_PANEL_PATH/' \
  --loopback-insecure
```

Если база расположена не по `/etc/x-ui/x-ui.db`, добавь `--db-file /путь/x-ui.db`.
Флаг `--loopback-insecure` разрешает несовпадение сертификата только у локальной
проверки панели по loopback. Он не меняет настройки HTTPS панели или нод.
При HTTP-панели укажи локальный http URL без этого флага.

### PostgreSQL (например, удалённая панель)

Сначала выгрузи **свежую резервную копию базы** через панель или pg_dump.
Установщик не извлекает пароль PostgreSQL из окружения и не делает вид, что
копирование `/etc/x-ui` сохраняет содержимое PostgreSQL.

```bash
sudo bash install-panel.sh --db postgres \
  --database-backup /root/panel-before-tunnels.dump \
  --health-url 'https://127.0.0.1:2053/YOUR_PANEL_PATH/' \
  --loopback-insecure
```

`--dry-run` проверяет комплект, исходную версию и наличие указанной базы/бэкапа,
ничего не меняя. Это не проверка полноценной установки и запуска служб.

Установщик:

1. Проверяет контрольные суммы и исходную версию 3.8.5.
2. Сохраняет бинарник панели, прежний комплект туннелей и метаданные в
   `/var/backups/3x-ui-tunnels-<timestamp>/` (доступ только root).
3. Останавливает x-ui; для SQLite делает согласованный снимок базы; сохраняет
   `/etc/x-ui` в закрытый архив. Для PostgreSQL сохраняет предоставленный экспорт.
4. Заменяет `/usr/local/x-ui/x-ui` и кладёт проверенные бинарники туннелей в
   `/usr/local/share/x-ui-tunnels/`.
5. Запускает x-ui и проверяет локальную страницу панели. При провале проверки
   восстанавливает предыдущий бинарник и пытается запустить его.
6. Проверяет, что SHA256 установленного Xray не изменился.

Он не переустанавливает работающие `olcrtc-telemost`/`turnrelay-vk`, не меняет их
ключи, ссылки или сертификаты. После обновления они подхватываются через UI.

## Подключение уже работающих туннелей

На главной панели → **Туннели → Подключить существующий**:

- VK: зарубежная нода удалённая панель, outbound `vk-tunnel`;
- Телемост: зарубежная нода удалённая панель, outbound `telemost-tunnel`.

Панель проверит роли client/server, совпадение ссылки Телемоста или отпечатка VK,
затем доступ в интернет. Совпадающий outbound сохраняется; конфликтующий не
перезаписывается. Рабочая схема резервирования продолжит использовать те же теги.
Секреты в браузер не возвращаются.

## Создание нового туннеля

На обеих VPS уже должны быть обновлены панель и комплект бинарников. В мастере
выбери «Установить и проверить», провайдера, зарубежную ноду, ссылку и имя outbound.
Для VK дополнительно укажи IP и UDP-порт зарубежного сервера. Открой выбранный
UDP-порт в firewall ОС и провайдера; мастер не меняет firewall автоматически.

Секрет создаётся на главной панели и передаётся ноде по её HTTPS API. VK закрепляет
SHA256 сертификата зарубежного сервера. Существующая установка не затирается.
Сначала проверяются параметры, локальные файлы и порт, затем устанавливается
серверная сторона, затем клиентская.

Распределённая установка не является атомарной: если нода установилась, а локальный
шаг завершился ошибкой, её файлы остаются для диагностики. Повторная установка
поверх существующей не выполняется. Ошибка говорит, какой этап требует внимания.
Если оба конца созданы, но интернет пока не доступен, пара сохраняется: закрой
мастер и повтори «Проверить / добавить outbound» после восстановления связи.

## Смена звонка и ограничения

В карточке → «Сменить ссылку». У Телемоста обновляются оба конца, у VK только главная панель.
Состояние `active` — состояние systemd, не доказательство работоспособности
канала. Проверка делает HTTPS-запрос к `api.ipify.org`; она не измеряет скорость
и не проверяет UDP. Поддержка UDP у VK сохраняется, у Телемоста TCP-only.

Для управления нодой нужен доступ к её API, желательно по независимому пути.
Если API ноды доступен исключительно через перезапускаемый туннель, связь с
управлением может оборваться во время операции: проверь оба конца вручную.
При потере связи между двумя шагами настройки общего звонка автоматический
откат не всегда возможен; интерфейс сообщает об ошибке, не скрывает её.

Кнопка перезапуска не трогает Xray или другую службу туннеля. Новые звонки
автоматически не создаются. CAPTCHA не решается автоматически. Удаление служб,
ротация ключей, несколько пар одного провайдера и управление произвольными
сторонними инсталляциями в этот патч не входят.

## Откат панели

Используй путь, напечатанный установщиком:

```bash
sudo bash rollback-panel.sh /var/backups/3x-ui-tunnels-TIMESTAMP \
  --health-url 'https://127.0.0.1:2053/YOUR_PANEL_PATH/' --loopback-insecure
```

По умолчанию возвращается бинарник панели и прежний комплект статических
бинарников. **База сохраняется**, чтобы не потерять изменения клиентов после
обновления. Службы туннелей продолжают работать вне панели.

Если осознанно нужен полный снимок SQLite на момент установки, добавь
`--restore-sqlite`: изменения базы после снимка будут потеряны. PostgreSQL
восстанавливается отдельно из сохранённого экспорта стандартными инструментами.
Архив `/etc/x-ui` автоматически не распаковывается поверх рабочей конфигурации.

## Для разработчика

`3x-ui-tunnels.patch` применяется к чистым исходникам 3x-ui 3.8.5:

```bash
git apply --check /path/3x-ui-tunnels.patch
git apply /path/3x-ui-tunnels.patch
cd frontend
npm ci
npm run gen
npm run build
cd ..
go build -trimpath -ldflags='-s -w' -o x-ui .
```

Также приложен `source.tar.gz` с уже изменёнными исходниками (без node_modules).
`call-tunnel-sources.tar.gz` содержит исходники использованных туннельных бинарников.
Требуются Go1.27, Node24 и C-компилятор для SQLite. Базовая версия панели остаётся
3.8.5; наличие раздела «Туннели» и этот архив идентифицируют локальный patch 2.

## Проверки и пределы проверки

- Go-тесты менеджера туннелей: ссылки, сохранность конфигурации, приватность файлов,
  откат при ошибке, отказ от перезаписи существующего туннеля, установка в тестовый root.
- Go-тесты API: admin разрешён; monitor/node-sync запрещены; HTTPS-вызов ноды и
  отсутствие утечки содержимого ошибочного ответа; контракт API-документации.
- Тест сохранности маршрутов/клиентов и конфликта outbound.
- Полные тесты затронутых Go-пакетов; race-тесты менеджера и клиента нод.
- Go-линтер, TypeScript, frontend lint; 138 файлов / 1520 unit и component тестов.
- Реальная сборка и вход в отдельную локальную панель, вкладка и валидация мастера.
- Скрипты обновления/отката протестированы с временными файлами и имитацией systemd.

Обновление выполнено на главная панель/удалённая панель (SQLite) и удалённая панель (PostgreSQL), подключение существующих
VK/Телемост через API проверено HTTPS-запросами. Полная новая установка из UI на
двух чистых VPS и полный Storybook/CI не проверялись. Это локальная сборка, не upstream-релиз.
