# Деплой панели из GitHub

Этот каталог управляет **фиксированным релизом `tunnels-3.8.5-patch4`**, а не сборкой текущего `main`.
Оригинальный проект: [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui), GPL-3.0.
Авторские уведомления и лицензия сохраняются. `vendor/install-fork.py` — копия установщика нашего релиза.

## Что запускается

Actions → **Infrastructure operation** → Run workflow, ветка `main`, Environment и операция:

| Операция | Поведение |
|---|---|
| `check` | Проверяет SQLite, службу панели, HTTP панели, конфигурацию Xray и заданные SOCKS-выходы. Не меняет панель. Временные файлы инструмента удаляются. |
| `install` | Ставит закреплённый форк на чистую Ubuntu 24.04+ / Debian 12+ amd64. При существующей панели отказывается. |
| `update` | Только для 3.8.5: делает зашифрованный бэкап, ставит patch4, сохраняет Xray и конфиги. Если patch4 уже установлен — только проверяет. |
| `backup` | На короткое время останавливает панель; создаёт согласованный архив и шифрует `age`. Панель запускается обратно даже при ошибке архивирования. |
| `restore` | Восстанавливает архив этого инструмента на чистую VPS; требует подтверждения остановки старого мастера. Сохраняет активность/автозапуск служб из снимка. При ошибке финальной проверки останавливает восстановленные службы. |

`check` не является полноценной проверкой клиентского VLESS/REALITY с телефона. SOCKS-тест проверяет интернет через выход панели. После миграции отдельно проверить реальный клиент и доменный TLS, **потом** переключить DNS.

Новая установка содержит панель и движки туннелей, но не клиентов, ноды или ссылки звонков. Их создают через UI/API панели. Для точной копии действующего сервера используется `restore`: он переносит базу, клиентов, существующие службы VK/Телемоста, ключи и сертификаты. Массовая генерация новых пар туннелей этим workflow не реализована.

## Настройка GitHub Environments

Создать нейтральные имена, например `master`, `node-1`. Имя Environment и выбранная операция видны публично — не использовать IP, домены или названия клиентов.
Разрешить деплой Environment **только из `main`**, ограничить права на запись в репозиторий; включить review для изменений `.github/workflows/` и `infra/`. При доступности добавить required reviewer на production Environment.
Workflow дополнительно отклоняет запуск не из default branch. Он не запускается из PR и не использует `pull_request_target`. Секреты Environment доступны только после его deployment rules.

В каждом Environment задать **Secrets**, не публичные variables:

- `SSH_PRIVATE_KEY`: отдельный ключ автоматизации, публичная часть которого добавлена в root `authorized_keys` целевой VPS. Не использовать личный SSH-ключ; ограничить запись `restrict` (SSH-команды нужны, forwarding/PTY — нет).
- `SSH_KNOWN_HOSTS`: заранее проверенный ключ хоста в формате known_hosts. Для нестандартного порта запись `[host]:port`. Не подменять проверку на `StrictHostKeyChecking=no` или слепой `ssh-keyscan`.
- `TARGET_CONFIG`: JSON по примеру ниже с реальными значениями **только в Secret**.
- `AGE_IDENTITY`: приватный ключ расшифрования age, нужен только для `restore`; для обычного бэкапа не нужен. Хранить резервную копию отдельно от GitHub и VPS.

Пример (значения вымышлены):

```json
{
  "host": "192.0.2.10",
  "user": "root",
  "ssh_port": 22,
  "public_host": "panel.example.org",
  "panel_port": 2053,
  "probe_socks_ports": [],
  "age_recipient": "age1_REPLACE_WITH_PUBLIC_RECIPIENT"
}
```

`probe_socks_ports` — обязательные рабочие локальные SOCKS-порты без авторизации. Указать выход панели для проверки интернета. Пустой список проверяет только панель/конфигурацию; это подходит для чистой установки. Не включать заведомо сломанный резерв, иначе проверка должна завершиться ошибкой.
На VPS необходимы SSH, root и Python 3.12 (рекомендуется Ubuntu 24.04; Debian 12 с Python 3.11 поддерживает безопасную распаковку начиная с 3.11.8). Workflow ставит age/curl/socat/cron через apt для операций с изменениями; не управляет firewall, Docker, сайтом или сетевыми настройками.

Создать age-ключ локально: `age-keygen -o recovery.agekey`. Не коммитить его. Публичную строку recipient записать в `TARGET_CONFIG`, приватную identity — в защищённое место и при необходимости в `AGE_IDENTITY`.

## Бэкапы и восстановление

Зашифрованные бэкапы остаются **на исходном сервере**, в `/var/backups/3x-ui-infra/*.tar.gz.age`, доступ только root. Workflow не загружает их в публичные Actions artifacts или Releases. Автоматическое внешнее хранилище пока не настроено: скопировать ciphertext вне VPS по SSH/SFTP. Бэкап на том же диске не защищает от удаления VPS.

1. Выполнить `backup`, сохранить зашифрованный файл вне исходной VPS.
2. Передать его на чистую целевую VPS. Получить SHA256 **зашифрованного** файла.
3. В Secret целевого Environment добавить `restore_path` (абсолютный путь на новой VPS), `restore_sha256`, остальные нужные параметры и `AGE_IDENTITY`.
4. Остановить старую панель и её туннели (либо выключить VPS). Последний бэкап должен отражать нужное состояние; во время миграции не редактировать старую панель.
5. Запустить `restore`, отметить подтверждение остановки старого мастера.
6. Проверить сайт панели с доменным сертификатом на новом IP и VPN-клиент. Переключить DNS отдельно.

Архив включает `/etc/x-ui`, `/usr/local/x-ui`, bundle туннелей, известные каталоги/units VK и Телемоста, `/root/cert`, `/root/.acme.sh`, `/etc/default/x-ui`, CLI. **Не включает** сеть, SSH, Docker, произвольные службы, файлы вне списка, PostgreSQL, системные crontab и state directories посторонних программ. DynamicUser StateDirectory создаётся systemd заново. Сертификаты, размещённые вне `/root/cert` или `/root/.acme.sh`, и сторонние зависимости необходимо перенести отдельно. При внешней БД этот инструмент не использовать.

Старые ручные архивы миграции не подходят: инструмент требует manifest состояния служб. Сделать новый бэкап через `backup`. После restore проверить настройку продления сертификата: общий root crontab намеренно не копируется. Можно включить нужную задачу в `/etc/cron.d/xui-infra-acme` на исходном сервере — этот файл сохраняется.

## Обновления и откат

Установщик новой панели проверяет SHA256 двух фиксированных релизных архивов; версия Xray определяется закреплённым upstream-архивом, а не `latest`. `update` **не заменяет Xray**, даже если upstream выпустил новую версию. `restore` сохраняет бинарники снимка.
При провале внутренней проверки панели updater возвращает предыдущий бинарник. При ошибке дополнительного SOCKS-теста версия не откатывается автоматически: причина может быть во внешней сети. Бэкапы updater находятся в `/var/backups/3x-ui-tunnels-*`; для ручного отката использовать `deploy.py rollback` из релиза. Восстановление всей базы поверх работающей панели намеренно запрещено.

## Публичные логи

Никаких конфигов/баз/ключей в Git. SSH и Ansible output полностью перехватываются, в Actions выводится только результат. `no_log` защищает задачи; ошибки транспорта также не публикуются. Нет debug-режима и upload-artifact. Ошибки изучать через SSH на сервере, не включая печать секретов в workflow. GitHub и runner обрабатывают Secrets; люди с правом изменить доверенный workflow могут получить к ним доступ.

## Локальные проверки

```sh
python3 -m pip install 'ansible-core==2.18.6'
python3 -m unittest discover -s infra/tests -v
ansible-playbook -i 'target,' infra/playbook.yml --syntax-check
```

Для локального запуска задать те же переменные окружения, затем `OPERATION=check python3 infra/dispatch.py`. Не вставлять ключи в командную строку или shell history.

### Настроить Environment из защищённых локальных файлов

`configure-environment.py` создаёт/настраивает Environment с допуском только default branch и загружает три Secrets через stdin `gh`, не печатая их. Требует авторизованный GitHub CLI и **заранее согласованный** отдельный ключ автоматизации, уже установленный на VPS. Скрипт не добавляет ключ на сервер.

```sh
python3 infra/configure-environment.py --repo OWNER/REPO --environment master \
  --config /private/target.json --key /private/deploy-key \
  --known-hosts /private/known_hosts
```

Не хранить эти локальные файлы внутри репозитория. `AGE_IDENTITY` добавляется отдельно в Secret, только если нужен restore.

### Скачивание на личный компьютер

После успешного `backup` в Actions выполнить локально (SSH alias берётся из вашего `~/.ssh/config`):

```sh
python3 infra/download-backup.py --ssh-host YOUR_ALIAS --destination /private/vpn-backups
```

Скрипт скачает последний зашифрованный архив и сверит SHA256 с сервером. Существующий файл с другой суммой не перезаписывается. Закрытый age-ключ для скачивания не нужен. Он нужен для проверки расшифрования и восстановления; его отдельную резервную копию хранить вне этой VPS и не коммитить. GitHub-hosted runner не может сам записать файл на ваш ноутбук: эту команду запускают на ноутбуке после workflow.
